# Proyecto 3: Extensión lista para publicar

## Objetivo

Transformar una herramienta útil en un producto mantenible, con experiencia de usuario clara, instalación reproducible y documentación suficiente.

## Checklist de producto

### Funcionalidad

- [ ] Resuelve un problema real descrito en una frase.
- [ ] Tiene flujos básicos y casos límite definidos.
- [ ] Maneja ausencia de selección, entradas incorrectas y fallos de API.
- [ ] Respeta el sistema de deshacer donde sea posible.
- [ ] No elimina ni sobrescribe datos ajenos por accidente.

### Interfaz y calidad

- [ ] El panel está organizado y los controles tienen etiquetas comprensibles.
- [ ] Los errores son accionables y no solo mensajes técnicos.
- [ ] La ejecución de operaciones largas muestra progreso o se divide en pasos.
- [ ] Las clases, propiedades, handlers y timers se limpian correctamente.
- [ ] No contiene credenciales, rutas personales ni archivos de prueba innecesarios.

### Distribución

- [ ] `blender_manifest.toml` actualizado, si es una extensión moderna.
- [ ] Versión semántica y compatibilidad mínima comprobadas.
- [ ] Licencia correcta para código, iconos, modelos y documentación.
- [ ] README con instalación, uso, limitaciones y compatibilidad.
- [ ] CHANGELOG con cambios de cada versión.
- [ ] ZIP instalado desde disco en una instalación limpia.
- [ ] Código subido a GitHub y versión etiquetada.
- [ ] Video de demostración corto y capturas propias.

### Soporte

- [ ] Canal para informar errores.
- [ ] Plantilla de bug report con versión de Blender, sistema operativo, pasos y traceback.
- [ ] Política clara sobre actualizaciones y soporte.
- [ ] Plan de mantenimiento realista.

## Paquete final esperado

Un ZIP de extensión moderna validado, repositorio con código fuente, instrucciones de instalación y una demo reproducible. No publiques datos privados ni prometas compatibilidad con versiones que no hayas probado.
