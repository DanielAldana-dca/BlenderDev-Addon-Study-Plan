# Cómo contribuir

Las mejoras, correcciones, ejemplos adicionales y reportes de errores son bienvenidos.

## Reportar un problema

Incluye el archivo afectado, la sección, el resultado actual y el resultado esperado. Para errores de API, añade la versión exacta de Blender y un ejemplo mínimo reproducible. No incluyas tokens, credenciales ni rutas personales.

## Proponer cambios

1. Explica primero qué problema educativo resuelve el cambio.
2. Mantén el contenido en español claro y respeta los nombres oficiales de la API.
3. Cuando un ejemplo dependa de versión, indica la versión mínima probada.
4. Evita presentar una hipótesis de API como hecho sin validarla en Blender.
5. Comprueba que todos los bloques de código Markdown estén cerrados.
6. Actualiza `CHANGELOG.md` cuando el cambio tenga relevancia para los lectores.

## Estilo de documentación

Usa títulos descriptivos, pasos numerados cuando exista un orden, ejemplos breves y una sección de ejercicios. Prefiere explicar los efectos secundarios y las limitaciones antes que ofrecer un fragmento que pueda borrar o modificar datos sin avisar.
